# Вход по email, кабинет, география и валюты

## Подключение почтового входа
Код использует Supabase Auth (одноразовый email OTP) и уже существующее Redis-хранилище проекта.

1. В своём Supabase-проекте включить Email в Authentication → Providers.
2. В Email Templates для Magic Link и Confirm Signup вставить код `{{ .Token }}` в текст письма. Интерфейс ожидает именно код, а не переход по ссылке.
3. Подключить собственный SMTP для писем реальным пользователям. Стандартная отправка Supabase ограничена; перед запуском проверить доставку на внешнюю почту.
4. В Vercel → chari → Settings → Environment Variables добавить:
   - `SUPABASE_URL` — URL своего проекта.
   - `SUPABASE_ANON_KEY` — public/anon API key. Service role key здесь не нужен.
   - `KV_REST_API_URL`, `KV_REST_API_TOKEN` — существующие настройки Redis (также поддерживаются имена UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN).
5. Пересобрать deployment после настройки переменных и выполнить реальный вход по коду.

Без этих настроек кабинет честно сообщает, что вход ещё подключается. Заявки работают отдельно, как раньше.

После подтверждения email сервер создаёт непрозрачную сессию на 7 дней в Redis. Cookie имеет HttpOnly, SameSite=Lax и Secure на Vercel. В браузер не передаются токены Supabase. Есть лимиты отправки и проверки кодов и проверка Origin для изменений.

Кабинет показывает до 50 последних заявок только с подтверждённым email. Внутренние заметки админки не возвращаются. Заявки, оставленные только через Telegram, автоматически к почтовому кабинету не привязываются. Смена города в профиле действует для следующих заявок, уже отправленные заявки не переписываются.

## География
/api/context берёт приблизительную страну и город из заголовков Vercel. Вне Vercel возвращаются пустые значения. Координаты и разрешение браузера не запрашиваются; отдельному сервису IP не отправляется. Пользователь может исправить подстановку. Сохранённый профиль имеет приоритет.

## Валюты
/api/rates читает публичный API НБРБ. Курсы кэшируются на час, для RUB учитывается масштаб 100 единиц. BYN — базовая валюта данных заявки; остальные валюты служат приблизительным отображением. Если источник недоступен, доступна только BYN.

## Проверки
`npm test` проверяет маршрутизацию FAQ, курсы, вход через тестовую замену Supabase/Redis, изоляцию заявок, ограничения попыток, профиль, выход и приблизительную географию. Тест не отправляет писем.

Проверены браузером: четыре равные колонки, две колонки на 390px, корзина 35 BYN, свободный вопрос, реальный ответ API НБРБ и смена валюты, экран кабинета без настройки почтового сервиса. Отправку настоящего письма и работу с production Redis нужно проверить после подключения.

## Шрифты
На публичных страницах только Santa Catarina (заголовки), Geist Mono (интерфейс и текст), TT2020 Style E (заметки). Все файлы хранятся локально в fonts; лицензия Geist Mono включена рядом.
